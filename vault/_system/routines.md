# 定期処理の手順

動画の運用（深夜に前日の日報を整形、深夜2時ごろにノウハウ抽出、週1でまとめ、週1でエラー通知）を、
このリポジトリ（クラウドのセッション、コンテナは使い終わると消える）向けに置き換えたもの。
Claude に「〇〇の処理をして」と頼めばこの手順で実行する。定期実行したい場合は「スケジュールタスクにして」と頼む。

## 毎回（作業の終わり）— 日報の整形
1. `daily/_raw/<日付>.md` を読む（生ログ。Stop フックが自動で追記）
2. [[_system/templates/daily]] の形式で `daily/<日付>.md` を作成・追記する
   - 何を頼まれ、何をして、何が決まり、何が残ったか。細かい数字は消さない
   - 判断は `decisions/` に移し、日報からリンクする
3. プロジェクトノートの「未完了」「経緯」を更新
4. vault の更新も作業ブランチにコミット

※ クラウドでは翌日まで生ログが残らないため、動画のような「翌深夜にまとめて整形」ではなく「作業の終わりに整形」にしている。

## 毎回（作業の終わり）— ノウハウ抽出
その日の日報・解説した資料から、次も使えるやり方を `knowhow/` に抜き出す。
同じ種類の作業が 3 回以上出てきたら、Claude Code のスキル（`.claude/skills/`）にする候補として `knowhow/` に「スキル化候補」と書く。

## 週1（月曜）— ウィークリーノート
1. 先週の `daily/` をすべて読む
2. `weekly/<YYYY>-W<週番号>.md` を作る: やったこと / 決まったこと / 流れたアイデア / 来週やること
3. 先週 `sources/` に入れたものからノウハウにすべきものを選んで `knowhow/` へ
4. **点検**: 日報が抜けている日（作業したのに `daily/` がない日）がないか確認し、あれば報告する

## 月1（1日）— マンスリーノート
1. 先月の `weekly/` と `daily/` を読む
2. `monthly/<YYYY-MM>.md` を作る: 月の要約 / プロジェクトごとの進捗 / 決定 / 学び / ネタ帳（流れたけど今ならできそうなこと）
3. `projects/` が増えすぎていたら統合を提案する

## 未導入（必要になったら）
- エラー時のチャット通知: Chatwork / Slack などの API トークンが必要。導入する場合は Claude に頼めば、トークンを安全に登録する手順から案内する
- 会議の議事録・チャットログの自動取り込み: 取り込み元（Zoom / Meet / Chatwork / LINE 公式アカウントなど）を決めたら追加する
