## 3. コアメッセージ（持ち帰ってもらう3つ）

1. **成功は運の要素が大きい。失敗には必ず理由がある。だから失敗だけが学べる。**
   失敗の3病因＝情報不足・思い込み・自信過多。「成功は8割運」は統計ではなく著者の経験則として語る。
2. **AIは仮説検証の前半を担う。検証の後半は自分の足で。**
   仮説の棚卸し・反論出し・候補の絞り込みはAIが大半をやれる。実在の人に会う・売る・配信する後半は人間のデータが必須。小さい失敗を早く・多く回すと複利で効く。学生の4年間は失敗の単価が人生で一番安い。
3. **AI時代の仕事は「言われたこと」の外側にしかない。**
   AIを部下にして、自分は一つ上のレイヤーの仕事をする。言われたことを120〜140%で返すのが最低ライン。

## 5. 各パートのトーキングポイント

### ① オープニング＆自己紹介（10分）
- 最初の問い:「卒業まで、あと何回失敗できますか？」→ 挙手ではなく各自に数字を書かせる（最後に回収する伏線）。
- 経歴は「高卒・連続起業」を隠さない。早稲田の教室で高卒の人間が話していること自体が、学歴より行動を優先してきた証拠として機能する。
- 3回の失敗はそれぞれ「3病因のどれだったか」で語り、②につなげる。どの失敗をどの病因に当てるかは奥山が決める。
- 各失敗に添える「立ち直りのきっかけ」は1つだけ。複数並べると成功譚に戻る。語り順は「いつ・どんな失敗→原因→学び→今どう活かしているか」。主語は「自分が何をすべきだったか」。
- 「今」は叡智と建.LABOの第二創業支援に軽く触れるだけ。詳細は⑦で。

### ② 失敗の解剖学（9分）
- 成功は運の要素が大きい（著者の経験則として）。だから成功本を読んでも再現しない。失敗には理由があるので、フレームワークにできる。経営学の名著『失敗の本質』（中公文庫、累計100万部）も「なぜ失敗するか」を書いた本。1行触れる程度。
- 3病因の説明。各病因に自分の実例を1つ。学生版の例は出さず、ワーク①で学生自身に分類させる。
- 「この3つは、全部かつての俺」と言い切る。

### ワーク①（8分）
- 指示文に「相手の失敗には前向きな一言を返す」を入れる（文科省「Failure is Good!」の型）。
- 分類結果を匿名フォームに1行投稿。集計はその場でスクリーンに出してもよい。

### ③ 情報の洪水とAI（9分）
- 情報は不足ではなく過剰。毎日の情報の洪水で認知コストを使い果たしている。だから「選び方・集め方」がスキルになる。
- **割合ではなく工程で語る。** AIに任せる工程: 情報収集、構造化、反論を出す、候補案を粗く絞る。人が握る工程: 問いを立てる、全体をまとめる、人から引き出す、実際に会う・試す。「ここに価値が残る」。
- 産業能率大学の調査（2026年8月13日発表、在学生調査）: 生成AIの継続利用84.5%（前年57.7%）、利用経験96%、ChatGPT利用90.4%、Gemini 49.5%。マイナビ2027年卒調査では就活でのAI利用84.9%。この教室のほぼ全員が使っている。差は「使っているか」ではなく「どう使うか」。海外研究では「ChatGPTの使用は演習の成績を上げるが学習は上げない」（東大 吉田准教授の資料より）。
- 内部注記: 産能大調査のnと調査期間は原典未確認。引用前に確認。
- 無料で始められること: 調べ物は無料のAIで十分。有料は本気の作業にだけ使う。性能差とスキル差があるので「ペアで1端末」の逃げ道を用意。

### ④ AIで仮説を立て、自分で検証する（13分）
- ループ: 仮説を立てる→AIに反論させる→自分で小さく試す→直す。70点で動く（叡智のルール）。100点を待つと検証が始まらない。
- **言い換え後の核:** 仮説検証の前半工程（仮説の棚卸し、質問設計、候補案の粗い絞り込み、方向の確認）はAIが大半を担える。後半（実在の人での最終検証、個人の行動、少数派の反応、新しいカテゴリ）は人間のデータが必須。前半をAIで回し、人の検証を後半に集中させて「失敗の単価と回数を下げる」のが設計目標。「7割」「3分の1」とは言わない。
- 実例: 建.LABO 採用LPのA/Bテスト。鹿児島（友達・恋人と一緒に上京）と大阪（移住じゃない、挑戦。新幹線で2時間半）で訴求軸を分け、配信前にAIで候補を絞ってから出す。結果の数値を話すかは公開可否を確認してから決める。
- ライブデモ（7分）。お題は匿名投票で選ぶ（例:「サークルの新歓で新入生を2倍集める」「ゼミ発表で寝る人をゼロにする」）。AIに ①仮説3つ ②各仮説への反論 ③検証方法 を出させる。そのうえで2手順:
  - 同じ仮説3つの提示順を入れ替えて再実行し、判定が変わるのを見せる（LLMの判定は提示順の入れ替えで約4分の1が反転するという研究がある）。
  - AIが「全員賛成」を返したら、「合成の回答は人間より分散が狭い。全員賛成は疑え」と一言。
- 架空ペルソナの話は「捏造する」ではなく、**「それっぽい平均を返し、全員賛成しがちで、実在の人が持つ分散や驚きが消える」**と言う。実在の人のデータに接地すると精度とバイアスが改善する研究がある（Stanford、2024年。本人インタビュー接地で人間の自己再現性の85%、属性のみは74%）。「85%一致」とは言わない。
- 「AIは予選、本選は自分の足（実配信・実在の人）」で締める。
- サクセスホール: 1枚だけ。「成功への動線（ホール）を設計しながら、計画の穴（ホール）を塞ぐ。脆弱性を見つけるまでループするAIの逆をやる発想」。名前だけ覚えてもらえばよい。

### ワーク②（15分）
- 個人7分→ペア3分→2〜3名が発表5分。奥山は即興でコメント。
- 問いかけ:「AIが出した仮説をそのまま読んでいないか」「反論もさせたか」「検証方法は自分の足で1週間以内にできるか」。

### ⑤ 複利と仕事論（5分）
- 複利: 小さな失敗×回数×時間。20歳の失敗は40歳の失敗より圧倒的に安い。
- 中小企業のリアル: 人が採れない。建設系の技術者の有効求人倍率は5倍超（職業全体は約1.1倍）。社長が一番優秀なまま。組織としてAIを使っている中小企業は2〜3割で、6割強は個人任せ（商工中金 2026年1月調査では64.9%）。だから叡智はAI社員・AI役員で埋める。
- 大企業のリアル: 誰かが辞めてもバックアップがいる。阿吽の呼吸で仕事が回る。どちらが良いではなく、見え方が違う。
- 仕事論: 言われたことだけをやるのは三流。言われたことを120〜140%で返す。AIを部下にすれば、下のレイヤーの仕事を任せて、自分は上のレイヤーをやれる。

### ⑥ 僕の1日（3分）

- 複数のAIに同じ成果物を評価させ、相互批判させてから仕上げる。
- 10か月でレベルが上がったのはAIのせいではなく、毎日アウトプットして晒したから。

### ⑦ 叡智の紹介とインターン募集（5分）

## 11. リスクと対策

| リスク | 対策 |
|---|---|
| 内容が難しすぎる（大井先生の懸念） | サクセスホールは1枚のみ。6段階ワークフローや収益設計の話はしない。専門用語は毎回言い換える |
| 自慢話・成功者の説教に聞こえる | 失敗の話を長く、今の話を短く。自責で語り、立ち直りのきっかけは1つだけ。「全部かつての俺」と言い切る |
| 数字の置き方で信頼を落とす | 「7割」「3分の1」「85%一致」「90%／10%」は言わない。工程で語り、研究は両側（支持と反証）を引く。産能大調査などは出典を明記 |
| 金融・補助金の話に流れる | 話さないと決める。質問が出たら「別の機会に」 |
| 建.LABO・顧客の内部情報を話しすぎる | 社名・数値の公開範囲を事前に確認。採用LPは公開前ゲート未通過なので、結果数値は出さないか匿名化 |
| ライブデモが失敗する（通信・AIの不調） | 事前収録動画をバックアップ。デモは「結果を見せる」より「問いの立て方と疑い方を見せる」に重心を置く |
| 学生のAI利用レベルに差がある | 無料ツールで可。ワークは「AIに3つ出させる」の一手順だけにする。ペアで1端末の逃げ道 |
| 授業内AI利用・録音の扱い | 所属学部の方針を確認。大井先生から事前告知で明示。録音は音声のみ・匿名化・引用は個別許諾 |
| 時間超過 | Q&Aを調整枠に。⑤⑥は8分で切れる構成にしておく |
| インターン募集が「勧誘」に見える | 大学側に事前に伝える。5分に収め、宿題と個別フィードバックという「与える」形で終える |
