## 1. 企画の核

**1行**: 「人がやるから失敗する。ならば、仮説検証の7割をAIに回させれば、失敗は3分の1になる。」

**論理**
1. 成功は8割が運なので再現できない。失敗には必ず理由があるので、フレームワーク化できる。
2. 失敗の理由は3つに集約される: **情報不足・思い込み・自信過多**（失敗の3病因）。
3. 3病因はいずれも「人が仮説を立て、人が検証する」工程で生まれる。
4. 仮説検証の7割（リサーチ、構造化、反論、合成ペルソナによる事前評価）はAIが代行できる。人は残り3割（実際に会う、売る、配信する）だけを握る。
5. だから失敗は3分の1になる。しかもループを回すほど、成功の確率は上がる。これを体系化したものが「サクセスホール」。

**なぜ今か**
- 2026年、大学生の84.5%が生成AIを継続利用している（産業能率大学 2026年8月）。若手は「使う」側にいる。一方、中小企業は人が採れず、社長が一番優秀なまま止まっている。両者の間に本書の読者がいる。
- 中小企業向けAI本は「ツール導入・業務効率化」が中心で、「失敗の法則 × 仮説検証 × AI」という戦略側の切り口はまだ空いている（第4節）。
- 建.LABOの第二創業という進行中の実例があり、「本に書けるだけの成功」が出ている。

## 5. 本書の独自性（3点）

1. **診断フレーム**: 失敗の3病因（情報不足・思い込み・自信過多）。経営者が自社と自分を1枚で診断できる。
2. **道具**: AIで回す仮説検証ループ。合格ライン70点、課題→解決策→価格→チャネルの4段階、PASS／PIVOT／ESCALATEの判定、合成ペルソナと「実在する投稿者から作るアバター」による事前A/Bテスト。読んだ翌日に真似できる手順として書く。
3. **実録**: 建.LABO 第二創業（2026年8月〜）。内装会社から「空間」の会社へドメインを再定義し、採用LPのA/Bテストや仮説検証をAIで回して、現場が「第二創業をやろう」と動き出すまでの記録。

加えて、**大学講師（経営学）× 連続起業家（実務）の共著**という構成自体が、理論と実践の両面からの信頼材料になる。

## 13. リスクと対策

| リスク | 対策 |
|---|---|
| AIツール名が刊行時に古くなる | 本文は原理のみ。ツール名・画面は付録に隔離し、読者特典ページで更新する |
| 「必ず成功する」と読まれる | 前提条件付きの表現。第5章で「穴を先に見せる」原則を自ら実践する。うまくいかなかった例も第11章に書く |
| 事例企業との関係悪化 | 第12節の許諾を刊行前に書面で取る。匿名化の選択肢を常に残す |
| 補助金・金融の話に見える | 書かないと決める。金融教育講座は「学びの設計」として書き、商品の話はしない |
| 大学規定（第一著者、兼業） | 執筆・講演は学術の派生として可（大井先生の確認済み）。クレジットは大学側に事前確認 |
| 奥山の経歴が「ふわっとして見える」 | 連続起業家・叡智代表という事実と、本文の実録で担保する。実績の固有名詞は書かない |
| 売れない | 1,000部の消化計画を先に持つ（第8節）。売上ではなく「経営者への手渡し」と「問い合わせ」を成果指標にする |
| 「サクセスホール」の名称 | 商標の出願を検討（ビジネスモデル特許は進歩性の面で難しいという見立て）。書名にはせず章タイトルで使う |

## 付録. 大井先生にまとめていただきたい論点（A4一枚で可）

1. 経営学の立場から見た「失敗」の捉え方。『失敗の本質』以降、何が語られ、何が語られていないか。
2. AIによる仮説検証を、既存の経営理論（リーン、ブルー・オーシャン、ストーリー戦略など）の地図のどこに置くか。
3. 講義で学生に見える変化。AIを使う学生と使わない学生で、発表や思考に差が出ているか。
4. スポーツビジネスの知見から本書に入れたい視点（例: 勝敗の非対称性、運と実力の分離）。
5. ご自身が書きたい章、あるいは加筆したい章。
6. 出版社・編集者の知り合い、過去の執筆依頼で接点のあった媒体。
